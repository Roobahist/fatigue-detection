# Modernization notes

This pass establishes safe foundations without rewriting experiment history. It adds documentation, a portable E15 dataset path resolver, explicit CLI overrides, pure label parsing, caching of DROZY KSS file reads per worker/process, and dependency-light regression checks.

The default E15 output root changes to `./outputs` (or `FATIGUE_OUTPUT_ROOT`) when `--output_dir` is omitted, and autogenerated E15 folder names use E15 rather than E14. Explicit output and resume paths take priority. The original HPC data location remains as a backward-compatible default.

Further E15 safeguards validate complete, subject-disjoint inner and outer fold partitions without changing fold assignment order. New inner folds no longer evaluate outer test data while searching configurations, retaining `outer_test_metric: null` for JSON compatibility; old records keep their historic numeric values. Direct E15 adapter calls without an output path now use a portable timestamped E15 folder under `FATIGUE_OUTPUT_ROOT` (or `outputs`). See [the E15 evaluation integrity report](e15-evaluation-integrity.md).

Historical `Zh` imports, E1-E14 code, archived notebooks, checkpoints, logs and plots remain in place. An archived scratch file, `src/process/archive/temp.py`, contains invalid Python syntax and is intentionally excluded from active-code compilation without deleting or rewriting history. Renaming or deleting them is unsafe without an end-to-end baseline and data provenance checks. A later dedicated migration can evaluate those changes, audited nested CV leakage, a portable dependency specification, and archival storage. Containerization is deferred until a reproducible GPU/HPC execution target is known. No deployment is introduced.
